# V2-01C-0：Agent 新增投递保存并同步投递管理

## 主链路

用户输入“今天投了浙江大华公司的大模型开发岗”后，规则 Agent 将其识别为
`preview_application`，解析公司、岗位、当天投递日期和默认状态“已投递”。未提供的地点、招聘类型、
投递来源、投递链接和备注在预览卡中显示为“待补充”。

预览阶段只在服务端保存带过期时间的 `preview_id`，不写入 SQLite。用户点击“确认保存”后，
前端只提交该 `preview_id`；服务端确认预览有效且数据库路径一致后才保存投递记录。

## 投递管理同步

投递管理页面每次进入时都会调用 `GET /api/v1/applications` 重新读取同一个 SQLite 数据库。
因此确认保存后切换到投递管理页面即可看到新记录；如果投递管理页面已经停留并保持挂载，
可使用页面刷新重新拉取数据。

## 安全边界

- preview 阶段不写数据库。
- confirm 只能使用服务端签发的 `preview_id`。
- preview 和 confirm 均不调用 LM Studio。
- LM Studio 继续只负责查询类回答润色，不参与写入判断和保存。
- 本阶段不包含重复检测、自动合并、编辑、删除或数据库迁移。

## 自动化验证

端到端测试使用 pytest 的临时数据库，覆盖意图识别、字段解析、确认前无数据、确认后保存、
投递管理 API 可查询新记录，以及整个写入链路不调用模型。
